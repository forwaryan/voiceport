The current downloadable runtime is sherpa-onnx 2.0.1, released from commit `af2d8d81dbfa61c4cea4c568da78f3982edca005`, with ONNX Runtime 1.28.2. Its C interface was compared against the retained header at https://raw.githubusercontent.com/k2-fsa/sherpa-onnx/af2d8d81dbfa61c4cea4c568da78f3982edca005/sherpa-onnx/c-api/c-api.h (retrieved 2026-11-17; SHA-256 `5698f38ba09ad2bdf085c56a6cbbd7741acf15e25f4ce5c7097b9702cadf437f`). The online recognizer and model configuration layouts used by VoicePort are unchanged. The 2.0.1 offline recognizer configuration appends `SherpaOnnxOfflineCtcFstDecoderConfig`, containing a graph pointer and an `int32_t` maximum-active count. `bridge.cc` supplies this zero-initialized tail in `OfflineConfigStorage`; the legacy runtime reads only the original prefix. The vendored header itself is not a copy of 2.0.1.

`bridge.cc` is VoicePort code. Its C ABI catches C++ inference exceptions before returning errors to Rust. Dynamic loading resolves required symbols and checks `SherpaOnnxGetVersionStr()` against the explicitly requested version before creating any recognizer. App-local rule admission runs the same loader on the staged engine and closes its handles without creating a recognizer. Recognition and retries use that staged engine. Only exact runtime versions 1.12.37 and 2.0.1 on Apple Silicon are supported. Parakeet Unified EN and multilingual Nemotron 3.5 require 2.0.1; older compatible models can retain 1.12.37. The old ONNX Runtime filename is `libonnxruntime.1.23.2.dylib`; 2.0.1 uses `libonnxruntime.dylib`.

The standalone CLI checks exact byte counts and SHA-256 digests for both native libraries against the release members pinned in `verified.rs`. The source archives are `sherpa-onnx-darwin-arm64` on npm. Version 2.0.1 uses the existing installer archive pin `afc9415260e232c4dadc25a29a8645acb0ba06ef989060d32274f4c749a4830e`. Version 1.12.37 uses the archive with SHA-256 `1ae67a3faa9abbd15e6b1096bee87c120f848f1e1d3f778cb80216886cab217b`, checked against the npm registry's SHA-512 integrity. Both pinned sherpa libraries resolve their matching ONNX Runtime from `@loader_path`. Other direct dependencies of these libraries are macOS system libraries or frameworks. The CLI copies and hashes the bytes from each open file into an owner-only directory, then keeps that directory alive for the native session. The bridge loads from that directory.

The bridge selects eight explicit model configurations: streaming Paraformer, offline Whisper Tiny, offline Whisper Large v3 Turbo, offline SenseVoice, offline Parakeet TDT v3, offline Parakeet TDT v2, streaming Parakeet Unified EN, and streaming multilingual Nemotron 3.5. Turbo and the new transducers use 128-dimensional features. TDT uses the native `nemo_transducer` backend and encoder/decoder/joiner files. Unified selects its dedicated buffered streaming backend through `streaming_model_type` metadata. Nemotron uses the encoder's language prompt dictionary and sets the pinned stream language with `SherpaOnnxOnlineStreamSetOption`; its upstream 2.0.1 backend removes prompt/language tokens from displayed transcription. SenseVoice uses the header's native SenseVoice fields, automatic/explicit language, and inverse text normalization.

The model library can explicitly download pinned runtime/model artifacts into VoicePort's user-data directory, with size and hash checks. Runtime npm archive installation also verifies registry SHA-512 integrity and extracts only the package metadata and two expected libraries. It does not run npm or package scripts. Compatible Orca dependencies remain read-only optional sources. Per-model licenses and attribution accompany both downloads and offline imports. See `docs/LOCAL_MODELS.md` and `model_library/catalog.rs` for exact artifacts and licenses.
