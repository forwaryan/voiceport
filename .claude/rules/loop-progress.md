# Loop 执行与等待

适用于本项目所有 loop，包括带自定义提示词的 `/loop`。

- 有已授权、依赖满足、当前能执行的下一步，就在当前轮连续推进。完成一个调查点、更新文档、保存计划、派发任务都不构成结束当前轮的理由。
- 派发后先做自己能独立推进的工作；全部剩余步骤确实依赖尚未返回的任务时，才结束当前轮等待完成通知。不得用无用 agent、空轮询或高频 timer 制造活动。
- 调用 ScheduleWakeup 前明确等待对象，并确认没有独立可执行步骤。后台通知为主，1200秒以上 timer 只作兜底；外部轮询按真实状态变化速度，用户明确要求的周期观察按授权节奏。
- 调度 reason 须遵守 [等待入口约束](../../docs/LOOP_METHODS.md#51-动态等待入口约束)。不得将可继续的本地工作标成 external/periodic 来绕过后台回执核对；周期观察须有实际用户授权。
- 完成通知到达后立即处理并继续推进依赖已满足的步骤；不要机械重新挂起20分钟。任务完成、用户暂停或只剩不能自行解除的阻塞时，停止自有调度，报告具体解除条件。
- 对用户准确区分正在前台执行、确实运行中的后台任务、只安排了未来唤醒。只有 timer 时不能说任务正在推进。
- 轮换、权限、冻结和暂停优先；等待声明不能解锁这些限制。原完整 loop 提示词保持不变。
