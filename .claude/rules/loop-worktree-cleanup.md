# Loop 合并与 worktree 清理

适用于本项目所有 loop，包括带自定义提示词的 `/loop`。用户于 2026-11-15 授权：代码合入 `main` 后可以删除对应 worktree；有代码未合入 `main` 的 worktree 一定不能删除。

- 每次合并后检查对应 worktree 是否可以清理，满足以下条件后通过 `orca-cli` 删除；主工作区保留。不得仅因目录旧、任务显示完成、分支干净或已有备份而删除。
- 删除前读取实际目标的分支和 HEAD，分别核对分支独有提交、暂存修改、未暂存修改、未跟踪文件，以及新增、删除、重命名和文件模式变化。源码、测试、配置、文档等有价值内容均须有明确去向，不能只检查 HEAD 或文件名。
- 必须证明所有待保留改动已完整进入当前 `main`。普通合并可核对提交祖先关系；squash、cherry-pick 或旧工作区内容已被后续版本包含时，须结合实际合并记录及逐文件/差异内容证明，保留 `main` 后续修复。仅提交到功能分支、PR 待合并、另存快照或复制到临时整合目录均不算合入 `main`。
- 任一改动未合入、只有部分合入、来源仍在变化，或无法确认合入关系时，保留 worktree，继续有授权的合并工作或记录具体阻塞；不得用强制删除、重置或先清空工作目录绕过。备份不能替代合入证明。
- 确认没有仍依赖该目录的活动写者、worker、构建或冻结验证；先结算任务并把必要证据保留到不会随目录删除的位置。删除前再次核对来源未新增改动，记录精确 worktree、来源 HEAD/内容摘要、目标 `main` SHA 与合入依据。
- 通过 Orca 的精确 worktree 选择器执行删除并保存真实回执，再核对 Orca、Git worktree 列表和目录状态。删除结果未知时先查实际状态，不重复删除。此规则不授权删除其他任务、主工作区或尚未合入的分支内容。

完整交付顺序见 [Git 交付与 worktree 清理](../../docs/LOOP_METHODS.md#61-合入-main-后清理-worktree)。保留当前权限、暂停、冻结与会话轮换约束；不改写已登记的原始完整 loop 契约。
