# 持续任务与自动交接恢复

适用于本项目的 loop，包括自定义 prompt。

- 有已授权且依赖满足的下一步就在当前轮连续执行；调查小结、保存计划、派发或收到任务完成通知都不能代替继续工作。
- 修改前读相关设计、规范与已证实教训，完成“真实待办 → 修复 → 必要验证 → 验收范围复核 → 下一项”的开发循环；已有下一步就在本轮继续。重复修复/错误验收记录规则、原因、证据和日期，跨三个不同日期重复后考虑提升规范；不自行新增每夜调度。
- 遇到可恢复故障，核对真实状态与副作用，执行有证据的恢复，再接续原任务。不重复未变失败、不制造空 timer。连续7次同工具/同参数/同结果后拦第8次重复调用，早于当前网关的8次截断，改做有依据的诊断；不能只改超时、包装或上限绕过。
- 临时失败须证实无副作用再有界验证；参数/依赖问题先修正；权限/暂停保留。未知 launch/close/写入只查原 journal 和真实状态，不重发。空回复/只有 usage、退出0或后台任务完成都不等于产品验收通过。
- 继任简报写清下一步、最新限制、证据路径和建议技能，引用已有产物，完整原契约按摘要保留；不把凭据或无关私人内容复制进启动 prompt。
- 先读 `.claude/COORDINATOR_ROTATION.md`，保留真实身份、压缩数、原授权和暂停。有明确故障恢复授权的持续任务在首个产品修改/后台派发前，用真实 human 原任务/恢复授权 UUID 执行 `session-task-register`，保存完整 task_prompt 与来源，不能编造 loop prompt；kind=task 不授予调度。独立顶层安装 loop 前仍登记完整原提示词和五字段契约。未注册且已 drift 的旧会话不得补造契约或改规则解锁，只能遵守真实显式授权的 fresh 行政接续。
- 已登记、无 Run、非 worker 的 Claude 顶层 terminal_drift：先精确停止本人全部调度，然后单独执行 `python3 -I .claude/hooks/coordinator_rotation.py session-recover --session ACTUAL_FENCED_SESSION`。使用该受限入口自动启动 fresh 管理会话并核验精确旧 PTY 退出和 fresh 产品继任，不让用户手开窗口/复制交接。
- 每次副作用先 journal；结果未知只核验真实回执，不 fresh 重发或重绑/清零。Run/worker 由原协调者 guarded stop/retry，不新建 Run 或接管其他产品。
- 暂停、权限/信任拒绝与原授权边界优先；恢复不授予联网、账户、录音/上传或 Git 权限。只有用户独有输入/授权等无法解除的条件阻塞时，完成其他独立工作并清楚报告条件。
- 当前没有独立步骤且确实等待已运行后台任务时才结束轮接收通知，通知到达立即继续；1200 秒以上兜底 timer 必须已有授权和真实等待对象。没有等待对象时停止自有调度。
