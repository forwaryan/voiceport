# VoicePort 使用指南

本页介绍日常操作与排障。首次构建安装见 [README](../README.md#快速开始)，升级与签名见 [macOS 更新说明](MACOS_UPDATES.md)。

## 菜单栏与窗口

VoicePort 启动后常驻 macOS 右上角菜单栏，不占用 Dock，也不会自动录音。首次普通启动会显示[就绪检查](#首次使用与自检)，不会自动请求系统权限。

- **左键点击图标**：展开快捷面板，查看当前来源、麦克风选择、听写状态和快捷键。可以直接开始、停止或取消听写，也可以打开「转写音频文件…」。展开「更多来源」后可以切换来源，或选择「添加转写方式…」。
- **打开完整界面**：从快捷面板打开工作台。侧栏按「工作」「配置」「系统」分组，首次进入显示「听写结果」。侧栏有焦点时，用 ↑ 和 ↓ 切换页面。按 Tab 进入当前页，按 Shift + Tab 反向移动。
- **右键点击图标**：打开工作台、转写音频文件、转写来源、麦克风设置或首次自检，也可以复制最近文字、取消听写或退出。
- **软件更新**：点击快捷面板的更新状态，或选择右键菜单中的更新状态，即可打开工作台的「软件更新」。在页面内可检查版本、确认下载或确认安装。 [更新与签名](MACOS_UPDATES.md)
- **显示听写提示**：在右键菜单切换录音和转写时的状态提示。提示在原输入位置附近显示，保留原焦点和光标。 [听写提示](DICTATION_STATUS_OVERLAY.md)
- **关闭完整窗口**：应用继续常驻。再次从快捷面板打开工作台，会回到上次选中的页面。点击面板外部或按 Esc 收起快捷面板。

菜单栏图标会反映听写、转写或待处理状态，并适配深浅外观。悬停可查看当前来源、状态与快捷键。来源较多时可以滚动查看；不可用来源会显示原因。快捷面板与设置页的选中状态同步，选择会保存供下次使用。打开面板时先显示已知状态，后台返回后更新相应行。仍可用的来源保留在原控件上，键盘焦点随该来源保留。

正常重新打开应用时展示快捷面板。App 已在菜单栏运行时，使用随包 CLI 直接打开完整窗口：

```bash
"$HOME/Applications/VoicePort.app/Contents/MacOS/voiceport" app show
```

App 尚未运行时，可以在启动时直接显示完整窗口：

```bash
open "$HOME/Applications/VoicePort.app" --args --show-window
```

`--args --show-window` 仅对新启动的进程生效；CLI 的 `app show` 通过本机 IPC 控制运行中的实例，不会自行启动 App。

### 菜单栏图标不可见

检查「系统设置 → 菜单栏」的显示开关。macOS 26 可能把终端启动的 VoicePort 归入启动应用的菜单栏组；此时 VoicePort 与启动应用（例如 Orca）的显示开关都需要允许。

菜单栏显示与辅助功能权限是两项独立设置，打开其中一项不会自动开启另一项。

## 快捷键与一次听写

默认快捷键是 **Control + Option + Space**：按一次开始，再按一次结束。在「设置 → 听写与快捷键 → 快捷键模式」可改成**按住说话**：按住组合键开始，松开结束并转写；在开始录音前松开会取消本次启动。两种模式都可通过菜单栏开始或结束，单次录音最长 **3 分钟**。旧设置保留原来的键位和切换模式。

1. 在菜单栏或设置中选好来源。
2. 回到目标应用，点好文字光标。
3. 按所选模式开始说话，结束后等待最终结果。
4. 检查输入框与结果面板，由你自行发送。

快捷键按下时会绑定目标应用。若随后 VoicePort 自己激活，程序先返回同一个目标应用并确认后再开始；若已经切换到其他应用、原应用退出或按键过期，本轮不会开始录音。

### 自定义快捷键

打开「设置 → 听写与快捷键 → 听写快捷键」，可选择 **Control + Option + Space**、**Control + Shift + Space**，或点击「自定义…」试按新的组合键，确认显示的键位后保存。

- 必须包含 Control、Option 或 Command，可再加 Shift。
- 支持字母、数字、常见符号、空格、方向键和 F1–F20；Esc、Tab、回车保留用于窗口操作。
- 按物理键位保存，字母和符号名称采用美式键位；切换输入法不会改变绑定。
- 试按不会开始听写。当前键位和试按结果显示在编辑窗口；系统确认组合键被占用时不能保存，其他注册失败会单独提示。按 Esc 或点击「取消」保留原设置。保存时会重新检查注册。

保存后立即生效，并在下次启动时恢复。菜单与面板提示同步更新；快捷键注册冲突会显示在设置中，可点击换一组。

## 来源管理与测试

在「设置 → 来源与模型 → 管理来源…」中添加、编辑、删除 HTTP 来源或导入插件；也可通过快捷面板的「添加转写方式…」进入。

「我的来源」按行显示配置状态、音频去向和最近一次适用于当前配置的测试结果。点击「音频去向」查看服务地址来源或外部程序类型。插件库的「详情」说明内置来源是在本机转写，还是将音频发给远端服务。本机 HTTP 服务和 JSONL 外部程序仍可能转发音频。VoicePort 无法确认远端服务或外部程序是否保留音频或何时删除。

**查看和保存配置不会联网或执行插件。** HTTP 服务与 JSONL 插件不要求安装 Orca，也不读取 Codex 登录。HTTP Bearer key 与插件 secret 字段按来源独立存入 Keychain，不转发给其他来源。

录音、转写期间不能更改设置，刷新来源期间不能切换来源。本次录音与后续重试固定使用开始时的来源、配置、凭据关联和语言；之后更改设置不会重定向已有录音。来源缺失、禁用或失败时会报错，不自动切换。

### 来源测试

在「设置 → 来源与模型」打开「测试各来源连通性与耗时…」，可逐项测试 ChatGPT、本地模型和自定义来源，或一键测试当前可用的来源。「我的来源」的「定位测试」会滚动到对应来源，测试由你另行启动。结果显示状态、样例总耗时与最近测试时间。

测试只在主动点击后运行，使用内置一秒静音样例；不启用麦克风、不投递文字、不切换当前来源，也不改已有听写结果。远程来源或外部程序可能联网并产生服务用量。静音测试用于连通性诊断，不能说明识别质量，也不能把不同来源的样例耗时视为语音识别性能基准。

接入细节见 [HTTP 与自定义来源](CUSTOM_SOURCES.md)、[JSONL 插件](TRANSCRIPTION_PLUGINS.md) 和 [本地模型](LOCAL_MODELS.md)。

## 首次使用与自检

首次普通启动会显示「首次使用与自检」。以后可在菜单栏右键菜单或「设置 → 输入与权限」中再次打开。窗口显示当前 VoicePort 实例的麦克风、可选语音预览、辅助功能授权和快捷键注册状态。只有点击相应的修复按钮才会请求权限或打开系统设置；「改为仅转写」会关闭自动输入并保存设置，不需要辅助功能授权。以后可在「设置」中重新开启自动输入。

点击「运行输入自检」，应用会把固定样例 `输入验证🙂` 插在专用测试框的 `A` 和 `B` 之间，并核对新光标位置、单次写入和光标移走后的拒写。每次点击都重置这个测试框，不会录音、联网、读取或改动剪贴板，也不会写入其他应用。通过仅代表应用内的投递和文本读回通过，不代表跨应用输入已经授权或目标应用兼容。实际快捷键可用性以独立的注册状态为准。

## 权限准备

| 权限 | 使用范围 | 缺失时的处理 |
| --- | --- | --- |
| 麦克风 | 所有来源的录音 | 无法录音，先完成系统授权。 |
| 辅助功能 | 自动向目标应用输入 | 开启自动输入时会在录音前提示；也可关闭自动输入，仅转写到面板。 |
| 语音识别 | ChatGPT 来源的可选设备端预览 | 可继续停录后转写；本地模型与自定义来源不申请这项权限。 |

在「设置 → 输入与权限」点击「未授权 · 设置」处理辅助功能授权。显式权限准备不会开始录音，本地与自定义来源的录音权限检查只检查麦克风。处理完系统提示后，回到目标应用，重新点好输入位置再开始。

同一组设置中的「麦克风设置…」可选系统默认或指定设备，并在授权后主动测试输入电平。 [麦克风设置与设备恢复](MICROPHONE.md)

开发包更新后，即使系统开关仍亮着，新包的实际权限也可能尚未生效。日常使用固定路径 `~/Applications/VoicePort.app`；签名连续性与重新授权说明见 [macOS 更新与权限身份](MACOS_UPDATES.md)。CLI 的 `doctor` 不申请或验证这些系统权限。

## 自动输入与恢复

应用会根据原输入位置的能力选择投递路径。可读写的普通字段可能更新本次听写拥有的文字范围；网页编辑区、Codex 与 Orca 聊天等路径可能在停录后分段键入最终文字；缺少标准文字接口的控件可能使用最终文字粘贴。具体路径、确认机制与实测范围见 [全局输入](INPUT_DELIVERY.md)。

自动输入不按回车，换行和控制字符会转换为空格；手动复制保留原文。焦点、文字、选区或用户操作变化时，会停止后续自动写入。单纯滚动不会取消，除非实际改变了输入焦点、文字或选区。

粘贴兼容路径使用剪贴板，最终文字留在剪贴板；期间进行其他复制、点击、编辑或切窗操作可能停止输入。密码、安全输入、明确只读或禁用的控件不会自动写入。输入事件提交成功只表示已发出请求，不能保证目标接收。

微信没有收到文字时，先按下方投递状态检查原输入框，再决定是否复制结果并手动粘贴。受支持的目标与限制见[微信兼容路径](INPUT_DELIVERY.md#目标与剪贴板)。微信识别来源尚未接入。

### 文字没有进入输入框

快捷面板的「本次转写」显示本轮投递状态。看到「等待输入」或「等待原输入框确认」时，等本轮结算后再处理。已提交、已部分投递或结果不明时，先检查原输入框再决定是否手动粘贴。已确认输入的文字无需再次粘贴。

点「查看本次文字」可展开并选择正文。「复制本次文字」每个结果只尝试一次，重新打开面板会收起正文，仍可自行选中文字。完整听写页可查看本轮诊断、复制正文或编辑临时副本。文字处理规则改变结果时，还可查看原始转写。 [个人词典、输出规则与听写场景](DICTATION_WORKFLOWS.md)

1. 确认授权的是当前固定安装路径中的 VoicePort。
2. 回到目标输入框，重新点好光标；使用全局快捷键开始新一轮。
3. 听写期间避免切窗、移动光标或编辑同一段文字。
4. 若目标控件不兼容，从结果面板复制文字并手动粘贴。

普通字段的文字、选区与光标更新会逐步确认；部分延迟读回会显示 `[readback]`。辅助功能授权本身不能使未提供系统文字接口的控件变为可写。

### 最近听写

在「设置 → 听写与快捷键」打开「保留最近听写」后，可以在工作台的「最近听写」或快捷面板查看记录。按时间和投递状态选择条目，再点「复制」。复制后可以自行选择粘贴位置。离开工作台的历史页、关闭或最小化窗口会收起正文。通过「清空」可立即移除记录。 [最近听写的留存规则](DICTATION_WORKFLOWS.md#最近听写)

### 取消与重试

取消后停止后续写入。普通字段中已经确认且未被用户改动的预览会尝试还原；未确认的写入可能保留已经生效的部分。**终端中已经输入的文字不会被撤回**，应用不会通过删除已有 CLI 内容来强行套用识别校正。

转写失败时，可在面板选择「重试这段录音」。不会自动重传，手动重试也不会把结果自动投递到新的输入位置。退出应用前，请先处理需要保留的文字或失败录音。

## 转写音频文件

从菜单栏右键菜单打开「音频文件转写…」，或点击「听写结果」页的「转写音频文件…」。CLI 可用 `voiceport app open files` 打开工作台的文件转写页，`app open file` 和 `file open` 也可进入。也可以把单个 WAV、M4A 或 MP3 拖到听写结果页或文件转写页。文件最多 **20 MB、180 秒**；不接受文件夹、符号链接或多选。选择或拖入不会开始转写，也不会改动源文件。

开始前会显示所选来源、语言和音频去向。文件页初始沿用当前听写来源和语言；可以另选支持该语言的文件来源，不会改变平时的听写设置。文件页给重复名称加上来源 ID，仍有重名时再加编号。选择来源后，页面会显示它的去向；所选来源不可用时，须重新选择才能开始。远端来源、本机 HTTP 或外部插件必须点「同意发送并转写」才会提交；发送给服务或插件的是转换后的音频，不含原文件名或容器元数据；本机 HTTP 或外部插件仍可能转发音频。来源失效或转写失败时不会切到其他来源。

文件转写与实时听写不能同时运行。文件页会显示转写、取消和失败状态。取消不会撤回已发送的音频。来源失败或取消结束后，可在原选择上点「重试转写」；外部来源每次重试都须点「同意发送并重试」。文件无法读取、解码失败或发生变化时，需重新选择音频。

文件页的「音频去向」对应当前选择，「转写结果」标明文字来自哪个文件。选取下一份文件时，上一次的结果保留到新任务开始。结果只显示在文件页，不自动输入、不改剪贴板，也不进入听写结果。可选中文字，或通过系统保存面板导出 TXT 或 Markdown；请用新文件名。导出失败不覆盖旧文件，也不丢失结果。Markdown 将正文保存为纯文字块。

## ChatGPT 登录与网络

ChatGPT 来源读取以下位置的文件登录：

1. 非空 `CODEX_HOME` 下的 `auth.json`。
2. 未指定时使用 `~/.codex/auth.json`。

只支持自己的 ChatGPT 文件登录，不支持 API key 替代或应用内刷新。通过 Codex CLI 执行 `codex login` 准备登录；其他来源无需此登录。独立文件转写命令还可通过 `--auth PATH` 显式指定文件。

macOS App 的 ChatGPT 请求使用系统中显式配置的 HTTPS 代理。应用与 CLI 也支持 `VOICEPORT_HTTPS_PROXY` 指定 HTTP / HTTPS 代理；URL 不接受用户名或密码。HTTP 自定义来源有独立网络策略，不沿用 ChatGPT 的代理行为，详见 [自定义来源](CUSTOM_SOURCES.md)。

CLI `doctor` 只查询登录文件的元数据，不读取或验证凭据，也不联网。文件存在和诊断退出 0 都不代表登录有效；详细状态、文件转写格式与退出码见 [CLI 文档](CLI.md)。
