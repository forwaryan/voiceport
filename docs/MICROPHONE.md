# macOS 麦克风设置

在「设置 → 麦克风设置…」或菜单栏右键菜单打开。打开面板和「刷新设备」只读取系统设备，不开始录音。

- **跟随系统输入（默认）**：每次开始时使用 macOS 当时的默认输入；VoicePort 不会修改系统默认设备。
- **指定设备**：选择只保存在 VoicePort。设备按 CoreAudio 的稳定 UID 区分，同名设备可看名称后的短标识。拔插后即使系统临时设备编号变化，也以 UID 为准，不凭名称猜测。设备不可用或列表读取失败时，原偏好仍保留。
- **系统默认输入与授权**：面板打开或点击「刷新设备」时在后台读取。读不到时会提示无法确认；后台忙时会等音频槽空闲。设备列表、系统默认输入和麦克风授权各有自己的结果。超过 15 秒或重新检查期间会标出旧快照；此时仍可保留保存的偏好，选择新的指定设备前须刷新。授权状态只供查看，开始录音与测试时会检查实际权限。
- **本轮实际输入**：成功打开且核对设备以后才显示。如果已回退，会显示实际设备及原因；断开恢复期间只有等待提示，替代设备通过检查后才显示新路由。停止过程中显示停止前的输入，平时设备栏不会把保存的偏好或系统默认输入显示为实际录音输入。

## 打开和停止麦克风

授权后，菜单和听写面板会显示「正在打开麦克风」。如果此时取消、在按住模式松开快捷键，或在切换模式再次按快捷键，本轮结束，保留之前显示的文字。打开超过 5 秒会提示超时。只有本轮仍有效、权限和设备检查通过后才接收采样和启动转写。

首次打开和断连恢复都会在后台核对实际设备的 UID、状态和格式。跟随系统输入或临时回退到系统输入时，还会在接入采样前重读 CoreAudio 的默认设备 ID。若读到不同设备，或在验证开始后、接纳前已收到默认输入变化通知，本次接入失败，该轮音频不会进入最终转写。系统属性读取与变化通知各自到达，检查覆盖最后一次读到的 ID 和接纳前收到的通知。明确指定且成功打开的设备按自身状态验证。录音接入后，仍正常工作的输入可继续使用。

麦克风设置和 CLI 的设备列表查询与录音、电平测试共享同一个后台音频执行槽。快捷面板的麦克风行独立读取设备名称，用来说明当前选择。实际录音仍会在开始时核对输入。一个操作还占用系统音频时，刷新设备或打开另一支麦克风可能提示忙。打开、恢复或停止超时后，本轮音频不会进入最终转写，面板和状态查询仍可用。如果 macOS 尚未完成设备调用，VoicePort 会等后台释放输入后才接受新的音频操作。可以正常退出 VoicePort。退出时会清除本轮尚未完成的录音缓存，即使系统音频仍在释放设备。如设备一直未释放，请退出后重新打开，再检查系统输入是否可用。

## 测试电平

空闲时点击「测试电平 · 10 秒」。须已允许麦克风权限；这个入口不弹出权限请求，也不会申请语音识别权限。它显示实际用于测试的设备和实时峰值（dBFS），区分已收到静音、尚无有效采样和读数过期。音频只在内存中用于测量，不保存、不转写、不发送，也不操作目标应用。测试期间不启动听写。面板发起的测试会在时间到、点击停止、离开设备页面、关闭面板、退出或设备失效时停止。CLI 发起的测试可用其操作 ID 停止。

## 断连恢复

开始时找不到指定设备、无法读取设备列表或指定设备打不开时，会尝试经独立查询确认的系统输入。回退只影响这一次，不改写偏好。录音中，VoicePort 保留当前仍正常工作的输入；插入新设备不会打断本轮。当前输入因拔出、合盖或系统音频重新配置而失效时，本轮最多恢复一次：先关闭旧输入，再按指定 UID 和系统输入的顺序重新选路。打开替代输入后，VoicePort 会复核实际设备和当前麦克风权限。跟随系统输入时也会复核默认设备。替代输入打开期间权限被撤销或所选默认设备已经变化，本轮会停止，不会进行最终转写。恢复成功后沿用本轮的计时与转写设置；设备断开期间可能漏掉一小段声音。下一轮仍以保存的偏好重新选择。

一次恢复后仍无可用设备，或恢复后的设备再次确定断开，VoicePort 会检查本轮私有缓存中实际录到的音频。只有文件归属可核实、能完整解码且含有足够信号时，才会保留片段。空录音、近静音、格式转换失败、输入归属不明、权限撤销和超时仍会结束本轮并清理缓存。Stop 遇到已确认的断开时可以保留片段。正在打开或核验替代设备时发出 Stop 会中止接入，本轮按失败处理。

在「听写结果」选择「转写片段」，核对录音开始时的原来源、语言及音频去向，再确认提交。确认前录音留在本机。结果标为「不完整」，可查看或复制。断连时停止原输入框的写入，保留已经出现的实时文字及原投递回执。片段成功转写、取消或开始下一轮都会释放录音缓存。CLI 对应入口见 [CLI 指南](CLI.md#interrupted-recordings)。
