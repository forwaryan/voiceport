# Local arm64 macOS development package

Run the complete offline path from any working directory:

```sh
python3 -I /absolute/path/to/voiceport/scripts/verify.py --app-smoke
```

Requires Swift 6 tools, Rust/Cargo 1.95, rustfmt, clippy, Python 3 and macOS codesign/lipo/plutil. Dependencies must already be cached: verification sets CARGO_NET_OFFLINE=true and uses the committed lockfile. No credentials are needed. Each run creates a fresh synthetic CODEX_HOME and canonical TMPDIR, removes only that owned temporary scope afterward, and saves complete per-command stdout/stderr, argv/cwd/environment differences, expected/actual exits and timeouts under `.voiceport/evidence/` (the exact report path is printed). CLI negative cases deliberately return 1/2 and are explicitly distinguished from failed verification.

The entry runs Rust tests/fmt/clippy, normal package (Swift and locked Rust release builds), Swift core/app/loop checks, PackagingTests, both actual release CLIs, bundle/notice/signature correspondence and helper ready/status/shutdown. `--app-smoke` additionally runs only the built bundle's `--smoke-test` menu path. That existing path returns before default recording cleanup and does not start a helper, read login contents, record/upload, show a normal window or inject input. No ordinary GUI launch is part of verification. Real active GUI exit and real users' audio/targets remain separate.

`bash scripts/package_app.sh` builds both releases. `--skip-build` performs no compilation but requires both products executable at Swift's reported bin path and Cargo metadata's actual target_directory/release. It still checks license resources, installs and signs. Extra/unknown arguments fail. Both package modes resolve the repo from the script, so external cwd is supported. CARGO_TARGET_DIR is honored through metadata, not an assumed cwd/target path. The reviewed package architecture is native arm64; no universal/Intel/Windows assertion is made. Package checking rejects missing/wrong helper, architecture, notice resources or signatures. A same-name independently ad-hoc signed copy of this Cargo product must hash identically to the installed helper; unsigned/original and signed bytes may differ.

Complete product manifests include `.gitignore`, Swift/Cargo manifests and lockfile, README/THIRD_PARTY_NOTICES, and all regular inputs under Sources/Tests/crates/scripts/resources/automation/docs, including new/untracked files. Entries have path/bytes/SHA256/mode and a directory set. New/deleted/content/mode changes fail start/end equality; symlink/special inputs fail closed. target/.build/dist, private evidence/coordination, root planning and generated pycache are excluded. This is a run-integrity check, not the coordinator's independent acceptance freeze.

## License materials

`resources/third-party/manifest.json` records the locked native target/feature graph, crate public source/version/SPDX, scope and choice, source-relative material paths, byte counts/hashes and Cargo input hashes. The installed copy is `Contents/Resources/third-party/`. Runtime reachability does not mean every object is linked. Build tools/proc macros, dev overlap and excluded-platform lock records are separately labelled. Dev/build materials are included conservatively; lock-only excluded platforms are recorded without pretending they ship in this native executable.

Full supplied license alternatives are retained. The recorded selection prefers MIT in OR expressions, else Apache-2.0; AND terms are retained together. Embedded components keep their own notices regardless of the crate-level choice. Source copyright/attribution files are copied in full as supplementary materials, including ring/BoringSSL/fiat/once_cell headers and license files. The MPL-2.0 package includes its complete cached package source rather than only a link. CDLA certificate-data and Unicode terms are included. Existing GPT Voice MIT attribution remains in the top-level notice and bundle.

To refresh after a deliberate dependency/feature change, run `python3 scripts/license_materials.py --generate`, review actual source materials/choices and the manifest diff, then verify. Packaging only checks; it never silently regenerates or uses a cache path as a substitute for shipped texts. Missing/unknown declarations, missing/tampered/unlisted resources and Cargo input drift fail. Only the native aarch64-apple-darwin graph is reviewed. This is local development material completeness, not legal approval, project license selection, notarization or permission for external release.

## Revision 01 trust boundaries

The public inventory uses schema 2: file rows preserve sorted(Path) order, directory names are sorted strings, and directory_modes maps every actual directory path to its POSIX mode. Canonical JSON (sort_keys, compact separators) of schema/missing/files/directories/directory_modes is hashed before adding sha256. Every required root and descendant is lstat checked before enumeration; missing roots, wrong types, symlinks and special files fail. Old three-field freeze digests and schema-1 public digests are different formats.

Bundle checking now requires three explicit paths: `python3 -I scripts/check_bundle.py APP RUST_RELEASE SWIFT_VOICEPORT_RELEASE`. Info.plist must equal the source plist, executable must be VoicePort mode0755, and both binaries must correspond to the specified current products. A same-name bundle twin is made with the actual Swift product and re-signed; its main executable must hash identically. This accounts for bundle Info/identifier signature slots rather than equating unsigned and signed bytes. No substituted main is executed. Normal packaging and skip-build still require both products; verify passes both resolved paths.

License checking reconstructs the expected native Cargo metadata package/feature/scope graph and reviewed choices from locked inputs and read-only cached upstream source. It recomputes the expected complete material set, bytes and hashes without writing or regenerating resources. The source manifest must match this authority, then the installed manifest must equal that validated source. Missing/extra/duplicate packages, unknown declaration or choice, omitted build inputs, changed feature/scope/source identity and self-consistent material omission fail. The cache is used as a pinned source reference, not as a substitute for installed texts. Native metadata features include conservative workspace/dev unification; the separately recorded normal/build Cargo tree distinguishes release reachability from that superset.
