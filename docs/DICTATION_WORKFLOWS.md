# 个人词典、输出规则与听写场景

从菜单栏选择「打开结果与设置…」，切到「偏好设置」即可找到「个人词典与输出…」和「听写场景…」。

## 个人词典

每行用 `→` 分开原词和替换文字。`北经 → 北京` 可以纠正识别错误，`签名 → 谢谢，我会尽快回复` 可以用口令展开常用短语。

匹配区分大小写，使用 Unicode 字素与词边界。`café` 能匹配由字母 `e` 和组合重音组成的等价文字，`app` 能匹配「用app」中的英文词。`apple`、`my_app` 和 `app’s` 的原有拼写保留。相同起点有多条规则时采用最长的匹配，替换后的文字直接输出。未匹配的文字保留原始字节。

词典规则保存在本机，在最终转写返回后替换文字。识别模型不会收到这些规则。

### 导入和导出

点「交换文件…」选择导入或导出。导入时选择「合并」或「替换全部」，预览完整结果后可应用到草稿或取消。合并保留草稿中已有的同名原词，并按文件顺序追加新规则。替换全部以文件内容为准，CSV 只有标题时可清空规则。应用到草稿后仍可继续编辑、预览示例或取消，点「保存」才提交。

导出读取已保存的规则，并原子发布到新的 `.csv` 路径，已有路径会保留。文件权限为 `0600`，仅当前用户可读写。导出会验证文件可重新打开读写，以及文件没有继承的 ACL 条目。检查或原子发布失败时可改用其他目录。发布失败后会清除临时文件正文；如果系统无法确认清除，错误会明确提示。

CSV 使用 UTF-8，标题为 `input,output`，按顺序记录原词和替换文字，支持 BOM、LF 和 CRLF。逗号和引号可以写在引号包裹的字段中，字段内的 `"` 写成 `""`。CSV 保留字段中的空格，含首尾空格的规则会在编辑器中以 CSV 显示。用表格软件编辑时，可把两列按纯文本导入以保留原值。旧 `.txt` 文件依然可按每行一条 `原词 → 替换` 导入，字段两端空白按旧规则裁去。

导入文件上限为 1 MiB。最多 256 条规则，原词最多 128 个 Unicode 标量，替换最多 512 个。原词和替换都须有非空白文字，字段内的控制字符（包括引号内的换行）和原词中的 `→` 会被拒绝。同一文件内规范等价的重复原词、缺列、坏引号、非 UTF-8 或超限会使整次导入失败，原规则保留。CSV 交换只包含规则，启用开关和场景继续保存在现有设置中。CLI 的预览、确认和取消命令见[离线 CLI 指南](../skills/voiceport/references/cli.md#dictionary-and-scenes)。

## 输出规则与预览

输入样例并点「预览」，依次对照原文、词典结果和最终输出。预览使用还未保存的编辑与开关；词典关闭时，词典结果等于原文。点「返回编辑」继续修改，点「保存」才应用设置。样例不保存、不投递。

本机处理顺序固定：先应用已启用的词典，再去除首尾 Unicode 空白，最后将 CRLF 和单独的 CR 统一为 LF。后两项各自可选，默认关闭。修剪会去掉首尾的空行，但不会删除夹在非空文字之间的空行，也不压缩内部空格。规则不运行脚本、不调用模型，也不访问网络。

预览的「最终输出」对应面板保留的正文，可以保留换行。自动写入以这段正文为输入，但仍遵守[投递保护](INPUT_DELIVERY.md)：换行和控制字符转为空格，不发送回车。预览不代表目标控件实际收到的文字。

开始 GUI 听写时固定来源、语言、词典和输出规则。手动重试使用同一快照。启用非空词典或任一输出规则时，中间结果仍在面板显示，非空的最终结果才进入自动投递路径。全部关闭且没有生效词典时，保留现有的实时输入路径与目标保护。仅当本次有非空最终正文且与原始转写不同时，完整听写页才会显示「查看原始转写」。纯空白格式化为空结果时，不投递，也没有原文入口。CLI 听写和来源探测保持来源原始返回文字；CLI 的分阶段预览只处理显式提供的样例。

## 听写场景

在「听写场景…」点「新建场景」，设置名称、来源、语言与个人词典开关。保存只添加场景，并记住当时的两个输出开关。要切换，选中一个场景并点「应用场景」，确认来源、语言、词典开关、输出规则与音频目的地，再写入当前偏好。来源配置在确认期间发生变化时，重新选择场景即可检查新目的地。来源已移除或不支持场景语言时，现有设置保留。

旧设置中的来源、语言及词典开关保留；旧场景没有输出规则时按关闭处理。

## 应用输出规则

在「偏好设置 → 应用输出规则…」填入一行 `com.example.Editor → 写作`，其中「写作」是已保存的听写场景名称。勾选「启用应用输出规则」并保存。功能默认关闭，关闭时保留映射。每个应用 Bundle ID 只能绑定一个场景，删除场景时一并删除关联映射。可通过 `plutil -extract CFBundleIdentifier raw -o - '/path/to/App.app/Contents/Info.plist'` 查看所选应用的 ID。

- **只应用输出设置**：原有写法 `com.example.Editor → 写作`，命中时使用场景的词典开关和输出规则，来源和识别语言仍使用当前全局设置。已保存的旧规则继续如此。
- **同时使用本机模型与语言**：先安装所需的[本地模型](LOCAL_MODELS.md)并保存一个使用该模型及受支持语言的场景。只给需要改来源的行加上 `本机 ` 前缀，例如 `本机 com.example.Editor → 写作`。命中时在本机转写，不改写全局来源和语言。只有 VoicePort 内置的本地模型可以这样选择；ChatGPT、HTTP（包括本机地址）和 JSONL 外部程序仍需按原入口显式选择。

应用匹配按前台应用的 Bundle ID 做区分大小写的精确匹配。全局快捷键使用按下瞬间的应用身份。按键已捕获且命中本机规则时，若按键过期或应用已退出或无法确认，面板专用模式也会拒绝开始录音。未命中、身份未知或从 VoicePort 自身开始时走现有全局路径及输入保护。规则只读取应用的 Bundle ID，不读取网页或 URL。

手动确认「应用场景」后，优先使用写入的全局来源、语言和输出设置，暂停应用匹配。该选择会保存；删除手动场景、在规则编辑器勾选并保存或运行 `voiceport app-rules enable on` 会恢复匹配。期间对全局设置的改动仍用于之后的听写。

启用并保存规则及每次命中时，都会检查本机模型、识别语言和引擎文件。保存与启动都用 macOS 加载预检检查引擎副本，启动成功后，本轮转写和重试使用同一份副本。预检会拒绝截断等无法加载的引擎文件。不可用时拒绝保存或在权限准备前拒绝本轮录音，并提示原因，不会改用全局来源。可先修复模型或场景，或显式移除该行的 `本机 ` 前缀再试。录音开始后固定模型、语言和输出设置。切换应用、修改设置或重试失败的录音都不会改变原去向；重试只在工作台保留结果，不会自动重投。

听写页和快捷面板会显示本次使用的场景或「全局规则」。快捷面板在本机规则命中时显示「本轮来源」及实际语言；听写页可在「展开投递详情」查看固定的来源、语言和本机去向。CLI 听写、来源探测和文件转写不按应用改选来源。可用 `voiceport app-rules match com.example.Editor` 检查所填 ID 的匹配关系，不用于证明模型就绪。命令详见 [CLI 参考](../skills/voiceport/references/cli.md#application-output-rules)。

## 最近听写

「保留最近听写」默认关闭。开启后，从新开始的 GUI 听写中保留最近的最终非空文字，按完成顺序显示。记录含时间和同一转写尝试的[投递回执](INPUT_DELIVERY.md#统一回执与重复结果)，所以也能找回投递失败或结果不明的文字。手动重试原本符合条件的录音时，成功的最终文字对应重试代次，状态为「未投递」。样例、后台和文件转写、已取消的听写和手动编辑的副本均排除。

每次运行最多保留 5 条，正文合计最多 48 KiB。单条正文最多 16 KiB，超长结果仅保留时间和投递状态，正文及复制功能不可用。超过总量或条数时优先移除最早的条目。历史内容仅驻留内存，开关本身保存在偏好中。「清空」、关闭开关和退出都会清除历史，进行中的听写也不会在之后补入。重新启动从空列表开始。

系统报告安全输入、辅助功能识别到密码字段或投递返回敏感状态时，本轮历史记录会被跳过或移除。外部应用的焦点角色须能通过辅助功能读取，权限或焦点信息不足时也跳过本轮历史。历史使用最终处理后的听写文字，不保存音频或手动副本。展开历史不改变剪贴板，点「复制」只将所选条目的完整正文复制到剪贴板。快捷面板的「本次转写」与完整听写页仍处理当前结果。

工作台的「最近听写」可以按正文和投递状态同时筛选。搜索忽略首尾空白和字母大小写，匹配保留正文中的连续文字。例如 `SS` 可以匹配完整的 `ß`，但 `as` 不会匹配 `AßB` 中的半个 `ß`。超长条目只能按状态筛选。点搜索框内的清除按钮可取消文字条件，选择「所有投递状态」可取消状态条件。离开或隐藏此页、清空历史、关闭保留或退出时，筛选和已展开的正文一并清除。无匹配和本次运行暂无记录分别提示。列表始终只显示时间和状态，显式选择一条才展开它，筛选移除选中条目时会收起正文。选中可复制条目后，复制按钮位于正文下方，并接入工作台键盘焦点顺序。

状态筛选使用同一条历史的回执。「明确失败」有失败阶段和未开始写入的证据。「未投递」包括仅面板结果和未写入即停止且没有失败阶段的结果。「未验证、未知或部分投递」包括已提交但未验证的事件、写入结果不明、部分投递，以及有写入证据但未完整确认的已停止结果。「等待投递或确认」适用于仍在等待的结果。「已确认」要求整轮完成、全部写入均有读回且未停止或失败。状态变化后按同一条目 ID 更新筛选结果。

复跑离屏原生控件夹具时，先在独占目录新建空的 PNG 输出目录，再执行 `cargo run --locked --offline -j 2 -p voiceport-macos --bin voiceport-macos -- --quick-panel-fixture <输出目录>`。夹具走 Controller 的最终结果与投递轮询，使用合成输入目标和内存复制接收器。它检查 AppKit 的可达性属性及本地键路，VoiceOver 实际播报需另行验证。

### 复制或重贴最近听写

在菜单栏右键菜单选择「复制最近听写」，然后到目标输入框手动粘贴。需要直接重贴时，先点好目标光标或选区，再按 `⌃⌥⇧V`。菜单会显示快捷键状态和最近操作反馈。听写快捷键已占用这个组合或系统拒绝注册时，仍可使用复制。重贴前后请在目标应用中检查文字，并按需自行发送。

这两个动作优先使用结果区仍保留的合格最终 GUI 听写。结果区已被替换时，只有开启「保留最近听写」才会从现有历史条目找回最近可读正文。历史关闭时，复制和重贴只借用现有结果区的文字。复用上述安全资格，排除 CLI、文件、样例、预览和空结果。历史单条的正文上限仍适用于从历史找回的结果。复制保留本轮开始时固定的输出规则所生成的最终正文及换行。重贴使用同一正文，写入时遵守[投递保护](INPUT_DELIVERY.md#显式重贴最近听写)，将换行和控制字符转为空格。

## 隔离投递验证

在独占构建目录中复跑以下命令。兼容性测试进入生产 `Delivery` 的捕获结算、最终文字和轮询路径，使用内存替身提供各类接收器的焦点、光标、读回、剪贴板和事件结果。它们把 `中🙂` 送到 `A|B`，检查最终文字与 UTF-16 光标、重复最终回调、迟到预览、离焦与未知写入。

```sh
CARGO_TARGET_DIR="$PWD/.voiceport/target-workflow-review" cargo test --locked --offline -p voiceport-macos --lib dictation_ -- --test-threads=1
CARGO_TARGET_DIR="$PWD/.voiceport/target-workflow-review" cargo test --locked --offline -p voiceport-macos --lib compatibility_matrix:: -- --test-threads=1
CARGO_TARGET_DIR="$PWD/.voiceport/target-workflow-review" cargo test --locked --offline -p voiceport-macos --test stop_failure -- --case gui-delivery
```

| 隔离接收器 | 观察点 |
|---|---|
| 原生字段 | 一次范围替换和文字读回 |
| 网页富文本 | Unicode 分段与写入后读回 |
| Orca 编辑器形态 | 标量事件顺序，读回期间离焦停止余下片段 |
| Orca 终端形态 | 只追加，回执记录事件提交 |
| 粘贴兼容形态 | 单次请求，回执记录事件提交 |

剪贴板和终端替身各自记录收到了什么，同时断言生产回执的确认次数为零。真实系统辅助功能捕获、WebKit 或浏览器 DOM、Orca/终端用户会话、全局按键和系统剪贴板需要各自的专用环境与测试授权。原生探针使用方式见 [输入投递](INPUT_DELIVERY.md#验证范围)。
