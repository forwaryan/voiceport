# VoicePort CLI reference

`voiceport [--json] [--socket ABSOLUTE_PATH] COMMAND`

`voiceport-rs` accepts the same commands. Global automation flags can appear before or after an App/Skill command; duplicate or unknown options fail. `--socket` takes precedence over `VOICEPORT_CONTROL_SOCKET`, then the default `/private/tmp/voiceport-control-UID/control.sock` on macOS. The chosen socket must be inside a same-user directory with mode 0700; its file has mode 0600. It must be an absolute real path with no symbolic-link ancestors. No implicit fallback to another instance occurs. A connection failure never starts the App.

## Offline commands

- `--version`: CLI package version and control schema.
- `help`, `--help`, `-h`: usage; legacy portable commands included. `sources --help`, `dictation start --help`, `dictation retry --help`, `qq doctor -h`, or `help sources` show the matching embedded reference section without connecting to the App, reading stdin/manifests, or running diagnostics. Unknown command paths still fail.
- `skills list`: bundled guides and installed version: `core`, `cli`, `workflows`, `plugins`, `plugin-examples`, `plugin-protocol`, `plugin-template`.
- `skills get [GUIDE]`: embedded content matching this binary; default `core`. `plugins` is the new-service onboarding Skill, `plugin-examples` covers compatible/local APIs and JSONL conversion, `plugin-protocol` is the manifest/execution contract, and `plugin-template` is the example Python adapter source (plain text; retrieval never executes it).

## QQ installation diagnostics (macOS)

`voiceport --json qq doctor [--qq /absolute/path/QQ.app]` runs the version-matched embedded, read-only installation checker without a running App, a checkout, a socket or network access. It requires an installed, usable `/usr/bin/python3`; the checker uses isolated Python mode and only the standard library. Omitting `--qq` checks `/Applications/QQ.app` and `~/Applications/QQ.app`; multiple installations require an explicit absolute path. `--socket` is rejected for this offline command.

The report checks the QQ bundle identity, official Tencent signature/team, sandbox entitlement and sealed entry resources. `checks` explains each inspection and `blockers` gives fixed reasons and recovery guidance. Exit 0 means the diagnostic report was produced, including when QQ is absent or unsupported; inspect `data.blockers`. It always reports `connection_status:"not_tested"`, `transcription_verified:false` and `automatic_setup_supported:false`. An installation check does not prove QQ can transcribe, and ordinary QQ does not automatically expose a VoicePort bridge. The checker never launches or modifies QQ, logs in, reads account/chat/Keychain data, connects to the bridge or uploads audio.

Missing Python, failed helper execution, invalid output and the 45-second outer deadline return fixed `diagnostic_unavailable`, `diagnostic_failed` or `diagnostic_timeout` errors without raw helper output. Other platforms return `unsupported`; their real QQ connection is unverified. This command does not install a bridge or offer an automatic connection route.

## App commands (macOS)

- `status` or `app status`: state, busy, pending/warning, discovering, selected source, language, version, bundle path, PID, socket and permission metadata. While stopping, `pending:true` and `warning:"cancellation_pending"` do not claim cleanup has completed. No permission prompt, auth read, transcript, target content or audio. `data.source_probe` reports the active CLI probe ID (null for GUI probes), engine `busy`, and `cleanup_pending`; these are independent of dictation's `state` and `pending`. `data.input` includes the GUI automatic-input preference, a content-free failure stage, and the last GUI start route with its outcome and session when assigned. Legacy target PID and bundle fields are null. `data.hotkey.registration` reports `registered`, `conflict`, `registration_failed`, `suspended`, or `unknown`.
- `status --expect-bundle ABSOLUTE_APP [--expect-pid PID]` also returns `data.readiness` from that same status request. Check `readiness.instance` for `matched`, `mismatch`, `not_running`, or `unknown`. A successful status request may report `mismatch` with exit 0. Only a matching instance supplies permission and hotkey facts for readiness. The check applies to that snapshot. Carry its socket and PID through the [automation workflows](workflows.md#connect-to-the-intended-app). `data.operation` is the active CLI dictation/test ID or `null`. The top-level App state may describe GUI work and carries no transcript.
- `app capabilities` reports the running App's `version`, `control_schema`, `platform`, `user_scope`, and supported command `groups`. An `app_update` list advertises the supported update verbs. Compare with `--version` and the installed CLI help before using a newer action.
- `app update check` explicitly starts the App's release metadata lookup and returns `data.state:"checking"` when accepted. It may access GitHub using the App's existing release configuration. A duplicate or a lookup blocked by a download, installation or quit returns exit 4 with `error.code:"busy"` and a snapshot. Once accepted, read `app update status` for completion. The user confirms downloads and installations in the workbench’s Software Updates page. The App verifies and stages the download before enabling installation.
- `app update status` reads the running App's `current_version`, nullable `latest_version`, `latest_version_stale`, `state`, `busy`, nullable `last_check_state` and `reason` without starting work. `last_check_state` describes the last lookup (`update_available`, `up_to_date`, `local_newer`, `incompatible`, or `failed`). `state` also reports `idle`, `checking`, `downloading`, `ready_to_install`, `installing`, or `quitting` as applicable. `latest_version_stale:true` means the known version predates a refresh in progress or a failed lookup. A successful status command can report a failed lookup. Use `app update --help` offline.
- `app show [--settings]` shows the running App window, optionally on its settings page. `app open PAGE` targets `result`, `settings`, `first-run`, `permissions`, `sources`, `source-tests`, `models`, `microphone`, `shortcut`, `dictionary`, `scenes`, `quick-panel`, or `files` (also `file`). Use `app open files` for the workbench’s file-transcription page. `app open quick-panel` exposes the native quick source selector, recent dictations and recovery controls.
- `app open first-run` and `app open permissions` show VoicePort's permission and input self-check panel. Use its individual grant/check controls and the macOS prompt or System Settings when required. `app open shortcut` opens the native shortcut recorder for a physical key combination and Save. `app open result` exposes the App's result, temporary edit and copy controls. Clipboard and focused delivery require a user action in their native context.
- Native steps return `page`, `state:"user_action_required"`, and `next` when further interaction is needed. Re-read runtime status/preferences after that interaction. `app quit` requests a graceful idle-only quit. Active work returns `busy`.

Launch is explicit and external: invoke the intended bundle's `Contents/MacOS/voiceport-app` or open that exact bundle after checking its path/version. There is no `app launch` command. For isolated tests, supply the socket/config environment to that exact child process before launch. Do not control a production App while validating a test copy.

### Delivery status

`data.input.gui_receipt` shows the latest GUI session with its process-local `session`, transcription attempt `generation`, `transcription`, `delivery`, `method`, `failure_stage`, and `block_reason`. Check the App PID alongside these identifiers. The receipt begins as `null`. Older Apps may omit it and retain an earlier round's `data.input.method` and `data.input.failure_stage`. `data.input.start` records the start route separately. CLI dictation keeps its own operation ID and `delivery:"none"`. A GUI retry retains its session and earlier delivery evidence while advancing the generation for transcription alone.

`data.input.gui_diagnostics` uses the same `session` and `generation`. A sealed `capture` shows its own capture generation, signal level, and observed counts. An audible signal can yield an empty transcript. Optional `timings` contain relative milliseconds for first valid input, target preparation, transcription, and final delivery when the relevant boundaries were observed.

`clipboard_final` is the final clipboard route, including the guarded WeChat main-window fallback. It uses Command+V without opening menus. A selected route may still wait, fail or be cancelled. Paste event submission leaves target receipt unverified. Check the running App version when interpreting the route. Older App builds used `wechat_menu_paste` for the previous menu path.

## Sources and plugins

- `sources list`: configured instances plus discovered catalog entries.
- `sources show ID`: one configured instance with config and Keychain references; secret values are never returned. Built-in sources appear in list/catalog.
- `sources add ID --plugin PLUGIN --name NAME [--enabled true|false] [--set FIELD=VALUE]... [--secret-stdin FIELD | --secrets-stdin]`: create a stable instance ID; disabled by default. Required configuration must be valid even when disabled. `--secret-stdin FIELD` supplies one required/optional secret atomically from piped stdin during creation. For multiple required secret fields, `--secrets-stdin` reads one JSON object mapping declared secret field names to string values (maximum 12 fields, 8192 bytes per value, 110000 bytes input). The two stdin options are mutually exclusive; no secret values go in arguments. A plugin can have multiple instances.
- `sources update ID [--name NAME] [--enabled true|false] [--set FIELD=VALUE]... [--secret-stdin FIELD | --secrets-stdin]`: update only supplied fields; empty VALUE removes a config field. Plugin identity/version and stable source ID are retained.
- `sources remove ID`: delete instance and its own Keychain items; selected source ID is retained as unavailable, with no fallback to cloud.
- `sources select ID`: persist the available source selection using the App's preference domain. Disabled/missing sources cannot be newly selected. Disabling/removing the selected instance preserves its unavailable selection.
- `sources destination ID` reads the current catalog's `source`, `destination.kind`, nullable `destination.origin`, `external_audio_possible`, and `languages`. An HTTP origin omits the path, query and credentials. Loopback services and external programs can forward audio. Local models advertise their language subset. For an external service, `languages` lists accepted VoicePort hints; the service decides what it actually recognizes.
- `sources secret ID FIELD --stdin`: read a nonempty secret (maximum 8192 bytes, trailing CR/LF removed) from stdin into the App's Keychain transaction. Never supply the value as an argument. EOF without input fails; no interactive prompt is generated. The shared App Keychain transaction additionally requires each stored value to be at most 4096 bytes without control characters, matching GUI validation.
- `sources secret ID FIELD --remove`: remove that field's independent Keychain item, subject to the same validation as GUI edits.
- `plugins list` / `plugins show ID`: built-in and imported versioned descriptors, schema fields, program/argv/origin.
- `plugins import MANIFEST.json [--accept-program]`: inspect a local regular manifest up to 32768 bytes. Without acceptance, return `confirmation_required` and descriptor details without persisting or executing. With acceptance, validate and import, still without execution. JSONL programs run with current-user privileges when later explicitly tested or used; no sandbox is provided. Duplicate plugin IDs are rejected.
- `sources probe ID|--all [--language CODE|auto] [--accept-upload]`: independently test one catalog source or all catalog entries, including ChatGPT, installed local models, and configured HTTP/JSONL instances. Without acceptance, return `confirmation_required` and destination/sample metadata without executing. With acceptance, run built-in one-second silence sequentially and return an operation ID. Disabled/unavailable entries produce failed rows without execution. Default language is `auto`; options can appear in any order. Use `--source ID` instead of the positional ID for an ID beginning with `-` (for example `sources probe --source -lab`); `--source --all` tests the source literally named `--all`. Do not combine a source selector with batch `--all`. To keep batch proposals within the IPC frame limit, their rows include stable source/plugin IDs rather than repeated program/endpoint details: inspect `sources show ID` and `plugins show PLUGIN` for every configured destination before accepting a batch. Single-source proposals include endpoint/program/origin metadata. The App's selected source, language preference, transcript, retained recording and delivery state are preserved. No microphone, target capture, clipboard write or automatic delivery occurs. Local probes load the installed runtime/model; cloud sources may upload the sample, and adapters execute with current-user privileges.
- `sources probe-result OPERATION`: read that CLI probe's report, including `state`, `busy`, `pending`, `language`, `all_passed`, and `results` with stable source IDs, `status`, nullable `elapsed_ms`, and nullable `completed_at_unix_ms`. Row statuses are `pending`, `running`, `success`, `failed`, `timed_out`, `cancelled`, or `cleanup_pending`. No recognized text, raw service errors or credential values are returned. Elapsed time measures worker execution, including authentication/connection/model loading; queue and polling delay are excluded. Exit 0 means the report was retrieved: check `state:"completed"` and `all_passed:true` for a successful finished run. Synthetic silence tests connectivity/execution, not recognition quality. Reports are ephemeral and replaced by a newer CLI probe; a later GUI run cannot be read as an earlier uncollected CLI run.
- `sources probe-cancel OPERATION`: cancel only the matching active CLI probe and queued entries. `busy:true` remains until resources are released. `warning:"cleanup_pending"` blocks new work and graceful quit; only a further explicit user-requested cancel asks for one background cleanup observation, without another termination signal. Do not repeat cancellation automatically. Read-only result polling does not request cleanup observations. GUI probes cannot be cancelled using a CLI operation ID.
- `sources test ID [--accept-upload]`: compatibility command for configured HTTP/JSONL instances. It uses the original dictation test lifecycle and may replace the existing dictation result; prefer `sources probe` for independent diagnostics. Without acceptance, show destination/sample information and fail with `confirmation_required`; with acceptance, send one-second silence and return an operation ID for `dictation result/cancel`. No microphone, target capture or delivery.

Configuration reads/writes and credential pinning use a background worker. Busy/discovery/configuration transitions can return `busy`; inspect status and wait for idle before a new user-requested mutation. Failed validation never silently changes selection or falls back to ChatGPT. A storage error after rename can have committed; inspect the store before deciding to retry.

## Dictation and test operations

`CODE` uses the model window's stable speech-language list, for example `zh`, `en`, `ja`, `ko`, `yue`, `fr`, `de`, `ar`, `hi`. Use `auto` to omit a language hint. Models and services support subsets; an unsupported local-model language fails before recording. HTTP forwards the selected explicit code to the service, which determines its supported languages. Codes are case-sensitive; unknown values and regional variants such as `en-US` are rejected by these App commands.

- `dictation start --source ID [--language CODE|auto]`: explicitly start recording using a pinned source/language and no automatic text delivery. Source and language options can appear in either order; duplicate/unknown options fail before connecting. CLI recording uses only existing microphone/Speech grants and never invokes OS authorization requests. Microphone permission must already be granted; missing optional Speech permission disables device-side preview only. GUI preference values are unchanged.
- `dictation stop OPERATION`: stop that CLI recording and perform same-source transcription. During microphone opening (`status.data.opening_microphone`), stop cancels the operation. For startup state and recovery, see the [CLI guide](../../../docs/CLI.md).
- `dictation retry OPERATION`: explicitly re-transcribe the retained failed CLI recording with the same pinned source/language and `delivery:"none"`; no new recording or source/language override. Requires the original matching CLI operation ID and Controller generation, failed state with current `retry_available:true`, and no busy work or pending cleanup. Rejects GUI operations, superseded generations and legacy `sources test` synthetic operations. Acceptance returns a **new** operation ID; the old ID then returns `not_found`. This may upload the recording again and requires explicit user consent; never use it as an automatic failure/transport retry.
- `dictation cancel OPERATION`: request cancellation of that CLI operation, including a synthetic test. `stopping` remains busy until the worker has released its resources.
- `dictation result OPERATION`: read only the current CLI-owned operation. Running replies contain `operation`, `state`, `busy`, `pending`, and `warning`. A ready reply contains `operation`, `state:"ready"`, `text`, `empty`, and `delivery:"none"`. A settled cancellation returns `error.code:"cancelled"` and exit 130. Terminal transcription failures include data `{operation,state:"failed",retry_available:bool,delivery:"none"}` alongside the error. For a read without text, use `status` and correlate `data.operation` while the job is active. Retry availability depends on the current retained recording and Controller generation. A later GUI generation invalidates an earlier availability report. Results are ephemeral and a newer CLI operation replaces the previous result.

These commands never deliver text to an input target or clipboard. Stop/result/cancel require the current ID returned by start/test/retry; retry is restricted to failed CLI recordings. They cannot take over a GUI operation. `result` may contain explicit user-requested text and should not be logged as default diagnostics. Preserve the same socket throughout; a lost retry reply is ambiguous, so inspect status/results without automatically resubmitting or starting a replacement.

`dictation gui-result GENERATION [--original]` is an explicit read of the retained final GUI result for the current generation. Get `generation` from `status` at the verified App PID. `--original` selects the source text before dictionary and output rules when retained. An empty final has `empty:true` and empty `text` even with `--original`; there is no separate original view for it. The reply has `generation`, `original`, `empty`, `text`, and `receipt`. Stale generations return `not_found`. The native result page can display transcripts beyond the CLI's frame budget.

- `dictation copy-last` explicitly copies the latest eligible GUI result to the macOS clipboard. The reply contains `generation`, `copied`, and `possible_duplicate`, with no transcript. Without an available result it returns `not_found`.
- `dictation paste-last --target-pid PID --target-bundle ID` explicitly submits that result from the running App to the named frontmost process. Both flags are required. Keep the intended field and selection focused from the time you request the action until it settles. The reply contains `generation`, `delivery`, `method`, and `failure_stage`. A successful response can still be waiting for readback. Check `status.data.input.repaste` on the same App and socket for the settled receipt. An unreadable or changed target returns `paste_blocked`. An earlier uncertain, partial, or unconfirmed submission, or a prior repaste that may have written this result, returns `possible_duplicate`. Check the field before using `copy-last` for manual paste. After a lost reply, inspect the receipt and the target before any further user-requested action.

These actions use the eligible result still visible in the App, with a fallback to an eligible entry only when history is enabled and its text is available. `app capabilities` advertises both verbs in `data.dictation_output`. The [delivery policy](../../../docs/INPUT_DELIVERY.md#显式重贴最近听写) describes target and duplicate protection.

## Preferences

- `preferences get` reads `source`, `language`, `languages`, `automatic_input`, `status_overlay`, `recording_mode`, and `shortcut` (`label`, `registration`).
- `preferences set language CODE|auto`, `preferences set automatic-input on|off`, `preferences set status-overlay on|off`, and `preferences set recording-mode toggle|hold` persist through the running App. Make settings changes when idle. Speech language validation uses the selected source's supported hints. Changing automatic input applies to subsequent GUI dictation. Changing the recording mode discards old queued shortcut edges.
- `app open shortcut` requires a real keypress and explicit Save in the native recorder. Read `preferences get` after saving to verify the binding and registration.

## Microphone

- `microphone list` shows CoreAudio input devices (`uid`, `name`, `label`) and the saved `preferred_uid`. `microphone select --system` uses macOS's default input for future starts. `microphone select --device UID` uses the exact reported device UID. VoicePort keeps its own preference.
- `microphone status` shows `permission`, `preferred_uid`, and nullable `active_route`, distinct from the preference. `microphone test-start --confirm` requires explicit approval and an existing microphone grant; it returns `data.test.operation` for the ten-second RAM-only level measurement. During the test `data.test.running` identifies active CLI work and `data.test.detail` contains the localized level/device reading. `data.test.device_in_test` includes any App level test. `microphone test-stop OPERATION` addresses only the matching accepted CLI test.
- `microphone open` opens the same native settings and level meter. Level testing uses microphone samples solely to measure input and performs no transcription, persistence, or upload.

## Local models

- `models list` returns the fixed library catalog with IDs, names, language summaries, bytes, availability and selection. `models details ID` adds the VoicePort-owned installation state. `models refresh` requests App catalog discovery. Read `models list` after `discovering:false`. Switch with `sources select ID` only after the user confirms that available model.
- `models recommend [--language CODE|auto] [--preview any|live|after-stop]` reads the current catalog and defaults to the saved dictation language and `any` preview mode. For example, use `models recommend --language zh --preview live` for Chinese live preview. The response includes the effective `language` and `preview`, `reason`, and nullable `recommendation`. `smallest_compatible_download` includes the model ID, pinned model download `bytes`, preview mode (`live` or `after_stop`), `available` in the current App catalog, and `selected` as the saved source. `no_compatible_model` returns `recommendation:null` with exit 0. `accuracy` and `performance` are `unmeasured`. Check `discovering` before relying on availability. The command only reads state.
- `models download ID`, `models update ID`, `models import ID ABSOLUTE_DIRECTORY`, `models remove ID`, and `models install-engine` prepare a proposal. `target.kind`, `target.model`, `target.may_download`, and byte counts describe the intended job. Imports verify the fixed model assets and may download the engine. Updates need a usable VoicePort-owned copy. Removal requires an unselected, VoicePort-owned copy and verifies the prepared directory identity under the production library lock.
- After explicit user acceptance, call `models start OPERATION --confirm` using the proposal ID. `models status OPERATION` reports `state` and optional transfer `progress`. Use the same ID to inspect a lost start reply. `models cancel OPERATION` addresses only that CLI job. A running cancellation remains `cancelling` until teardown. Verify actual disk availability with `models details` and `models list` after a terminal result. `models open` opens the same native model manager for interactive use.

## Dictionary and scenes

- `dictionary show` explicitly reads saved `enabled` and `rules`. `dictionary set on|off --stdin` replaces both from a pipe or file, with one `original → replacement` rule per line. Empty input clears rules. `dictionary preview --stdin` applies the saved rules locally to the supplied UTF-8 sample and returns `text` and `changed`. Both inputs are bounded to 24000 bytes. Preview works independently of the saved enable switch.
- `dictionary output show` reads the saved `trim_edges` and `normalize_newlines` switches. `dictionary output set trim-edges|normalize-newlines on|off` persists one switch, leaving the other and dictionary settings unchanged. Look for `dictionary_output` in `app capabilities` before using these additions; both switches default to off.
- `dictionary output preview --stdin` previews current GUI defaults with an explicit UTF-8 sample. It returns `original`, `after_dictionary`, final `text`, and `changed` (final differs from original). Input is limited to 24000 bytes, the dictionary stage to 32000 bytes, and the combined JSON reply to the IPC frame limit. Unlike legacy `dictionary preview`, this respects the saved dictionary switch and applies the enabled output rules. Final `text` represents the panel result, not the target write. It can preserve LF; automatic delivery still turns line breaks and control characters into spaces and never sends Return. Trimming removes leading/trailing whitespace (including edge blank lines), not interior blank lines. Preview does not record, save the sample or deliver text. `dictation result` still returns source text without applying these rules.
- `scenes list` returns saved scenes. `scenes add NAME --source ID --language CODE|auto --dictionary on|off` validates and saves a named scene with the current output switches, without applying it. `scenes remove NAME --confirm` removes the named scene. `scenes apply NAME` opens native confirmation for the settings and audio destination. Use `preferences get`, `dictionary show` and `dictionary output show` to verify what changed.
- `app open dictionary` and `app open scenes` open the corresponding native dialogs for interactive edits.

## Recent dictation

- `history list [--query TEXT] [--delivery confirmed|failed|uncertain|not-sent|pending] [--limit N]` returns `enabled` and up to five matching entries, newest first. The App matches `TEXT` as a case-insensitive substring of retained text after trimming the query. Omit either option to skip that filter. An empty query matches any text availability. A nonempty query excludes metadata-only entries. `failed` means a clear failure before writing, `uncertain` includes unverified or partial delivery, `not-sent` covers no delivery without a recorded failure, and `pending` covers waiting for delivery or confirmation. The accepted limit range is 1–100 and applies after filtering. List entries contain only `id`, `createdAtUnixMs`, `textAvailable`, `delivery`, `method`, and `failureStage`.
- `history show ID` explicitly returns `id` and `text`. An oversized eligible entry has `textAvailable:false` and returns `text_unavailable`. Evicted, cleared, and unknown IDs return `not_found`. IDs belong to the running App process.
- `history settings` reads the opt-in state. `history settings on` enables collection. Use `history settings off --confirm` to disable and clear old entries, or `history clear --confirm` to clear entries while preserving the setting. Clear returns `enabled` and `removed`. Collection starts disabled for first-time users and retains eligible GUI results in memory until eviction, clear, disable, or App exit.

## Single-file transcription

- `app open files`, `app open file`, and `file open` open the workbench’s file-transcription page and report `next:"choose_audio_file"`. Choose a single file in its picker or drop it on the Files or Dictation Result page. The CLI accepts an explicit absolute path through `file plan`.
- `file sources [--language CODE|auto]` lists eligible sources and their destinations. `file plan ABSOLUTE_AUDIO --source ID [--language CODE|auto]` opens the selected regular file read-only and snapshots the source before confirmation. It returns `operation`, `state:"planned"`, `target` and `delivery:"none"`. `target` contains `source`, `source_name`, `language`, and a tagged `destination` (`on_device`, `chat_gpt`, `http`, or `external_program`). HTTP includes an origin and a loopback flag. Once the App accepts a new plan request for validation, it discards the previous unsubmitted proposal, including when the new file or source fails validation.
- `file start OPERATION --confirm` submits the reviewed proposal once. Omitting `--confirm` on a planned proposal returns exit 5 with the proposal in `data`. WAV, M4A and MP3 input is limited to 20,000,000 bytes and 180 seconds. The App verifies the source snapshot and checks the selected file for changes before transcribing.
- `file status OPERATION` reads state without text. If the start reply is lost, query with the original proposal ID on the same App PID and socket. An accepted job reports the canonical `operation`, `generation`, `state`, `source`, `source_name`, `language`, `destination`, and `delivery:"none"` directly under `data`. `language:""` represents `auto`. Use either known ID while the receipt is retained. Job states are `working`, `cancelling`, `ready`, `failed`, and `cancelled`. For an accepted job, the status command can exit 0 with a failure or cancellation in `data.state` and a sanitized `data.error`. A rejected proposal can return an error envelope with `data.state:"failed"`. Progress is state-only.
- `file result OPERATION` explicitly reads `text` and `empty` when ready. For a failed or cancelled job, it returns a nonzero exit with `error.code` and the job data. While working or cancelling it can return exit 0 with state and no text. `file cancel OPERATION` cancels the matching CLI proposal or job. Wait for `cancelled` to confirm release. When a job has already settled, cancel returns its existing state. These file operations preserve the current dictation, recent history, and selected source.
- `file export OPERATION --output ABSOLUTE_PATH [--format text|markdown]` exports a ready result into a new `.txt` or `.md` file. The reply has `data.exported:true` and `data.format:"txt"` or `"md"`. An existing output path is preserved. For a lost export reply, inspect the exact output file before considering another user-requested action.

## JSON and exits

Automation commands with `--json` produce exactly one stdout object:

```json
{"schema_version":1,"status":"ok","data":{"state":"idle"},"error":null}
```

An error has `status:"error"`, `error:{"code":"busy","message":"..."}` and usually null data. Confirmation errors contain a proposed descriptor/destination in data; terminal dictation failures contain the operation/state/retry/delivery metadata described above. Parse `error.code`, never localized text. Diagnostics use stderr. Exit codes: 0 success; 1 operational/plugin/transport/permission failure; 2 invalid arguments/request/config; 3 app_not_running; 4 busy; 5 confirmation_required; 6 not_found; 7 unsupported; 130 cancelled. Exit 0 on submission means the App accepted the operation. For read commands, inspect the requested receipt: `file status` can report a failed job, `sources probe-result` can report `all_passed:false`, and `dictation result` can still be busy. A terminal dictation plugin failure uses `plugin_error`. Raw service bodies, adapter stderr and secrets are excluded.

IPC schema is 1, four-byte big-endian frame length plus JSON, maximum 262144 bytes, one request per connection and five-second total transport deadline. No automatic retries. If a reply is lost or deadline expires, a mutation may have happened: inspect state before deciding what to do next. Polling read-only status/result does not repeat uploads. Sockets are same-user controls, not protection from hostile code already running as that user.

## Original portable contract

`voiceport host [--auth PATH]`, `demo`, `doctor [--auth PATH]`, and `transcribe AUDIO [--language zh] [--auth PATH]` retain their original text/JSONL behavior and argument handling. The new global `--json`/`--socket` flags apply to automation commands, not these legacy commands. `host` already has its own bounded JSONL protocol. `transcribe` explicitly uploads the supplied file to ChatGPT using Codex file login and supports Ctrl-C cancellation; no automatic resubmission or delivery. This release has no `transcribe --source` option. Doctor checks only auth-file metadata. Windows retains the portable commands and offline guides; App control returns `unsupported`.
